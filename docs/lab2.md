# Лабораторная работа №2

Двухпросмотровый ассемблер для программы в перемещаемом формате.

## Задание

Доработать лабу 1 так, чтобы программу можно было загрузить по любому адресу. Ассемблер тот же, что в лабе 1 (директивы, форматы команд, ТКО, таблицы), добавляется только следующее.

- Программа транслируется с нуля: `START 0` или `START` без адреса.
- В правую часть окна добавить таблицу настройки - список адресов команд, которые надо настроить при загрузке.
- Добавить относительную адресацию: операнд пишется в квадратных скобках, `LOADR1 [B1]`, тип адресации в первом байте - `10`.
- На втором проходе:
  - прямая адресация - подставить адрес метки и занести адрес команды в таблицу настройки;
  - относительная адресация - записать смещение, в таблицу настройки не заносить.
- Режим адресации выбирается в окне: прямая и относительная, только прямая, только относительная.
- Примеры: только прямая адресация, только относительная, смешанная.

## Окно

Как в лабе 1, но вместо поля адреса загрузки - список «Адресация», справа добавилась таблица настройки:

```
+----------------------+-------------------------+-----------------------+
| Исходный текст       | Вспомогательная таблица | Заголовок             |
|                      |                         | Таблица настройки     |
| ТКО                  | ТСИ                     | Двоичный код (H T M E)|
| Адресация: [      v] | Ошибки 1-го прохода     | Ошибки 2-го прохода   |
+----------------------+-------------------------+-----------------------+
 [Первый проход] [Второй проход]                          Пример: [   v]
```

Щелчок по строке таблицы настройки или по записи `M` подсвечивает команду в исходном тексте. При выборе примера режим адресации выставляется сам.

Заголовок объектного модуля, как в лабе 1, показан отдельной строкой: `PROG 000068 000000` - имя, длина, начальный адрес (у перемещаемой программы всегда 0).

Поля «Адрес загрузки» здесь нет, как и в Zasm 2.0 на скриншотах методички: перемещаемая программа всегда считается с 0, а настоящий адрес загрузки выбирает загрузчик, ассемблеру он не нужен.

## Режимы адресации

| Режим | Что разрешено | Если встретилось другое |
|---|---|---|
| прямая и относительная | `LOADR1 B1` и `LOADR1 [B1]` | - |
| только прямая | `LOADR1 B1` | `[B1]` - ошибка первого прохода |
| только относительная | `LOADR1 [B1]` | `B1` без скобок - ошибка первого прохода |

## Относительная адресация

Метка в квадратных скобках - в команду пишется не адрес метки, а расстояние до неё:

```
смещение = адрес метки − адрес следующей команды
адрес следующей команды = адрес команды + её длина
```

Смещение занимает столько же места, сколько адрес: в формате 4 - 3 байта, в формате 3 - 2 байта. Отрицательное смещение записывается в дополнительном коде: −18 = `FFFFEE`.

Тип адресации - в младших 2 битах МКОП: `LOADR1 B1` - `02 * 4 + 1 = 09`, `LOADR1 [B1]` - `02 * 4 + 2 = 0A`.

Команды без адреса (`ADD`, `INT`) и данные (`WORD`, `BYTE`, `RESB`, `RESW`) в таблицу настройки не попадают.

## Пример «Только прямая адресация»

ТКО как в лабе 1.

```
PROG    START   0
        JMP     L1
A1      RESB    10
A2      RESW    20
B1      WORD    4096
B2      BYTE    X"2F4C008A"
B3      BYTE    C"Hello!"
B4      BYTE    128
L1      LOADR1  B1
        LOADR2  B4
        ADD     R1  R2
        SAVER1  L1
        INT     200
        END     10
```

Вспомогательная таблица:

| Адрес | МКОП | Операнд 1 | Операнд 2 |
|---|---|---|---|
| PROG | START | 000000 | |
| 000000 | 05 | L1 | |
| 000004 | RESB | 10 | |
| 00000E | RESW | 20 | |
| 00004A | WORD | 4096 | |
| 00004D | BYTE | X"2F4C008A" | |
| 000051 | BYTE | C"Hello!" | |
| 000057 | BYTE | 128 | |
| 000058 | 09 | B1 | |
| 00005C | 0D | B4 | |
| 000060 | 10 | R1 | R2 |
| 000062 | 15 | L1 | |
| 000066 | 18 | 200 | |

ТСИ: `A1 000004`, `A2 00000E`, `B1 00004A`, `B2 00004D`, `B3 000051`, `B4 000057`, `L1 000058`.

Двоичный код:

| Тип | Имя | Адрес | Длина | Машинный код |
|---|---|---|---|---|
| H | PROG | 000000 | 000068 | |
| T | | 000000 | 04 | 05000058 |

Таблица настройки: `000000`, `000058`, `00005C`, `000062` - все четыре команды с меткой. Записи `M` в двоичном коде - та же таблица настройки внутри объектного модуля.

Если загрузить программу с адреса `005000`, загрузчик пройдёт по таблице настройки и прибавит `5000` к адресам в этих командах: `05000058` станет `05005058`.

## Пример «Только относительная адресация»

Та же программа, все метки в скобках: `JMP [L1]`, `LOADR1 [B1]`, `LOADR2 [B4]`, `SAVER1 [L1]`.

| Команда | Адрес | Следующая | Метка | Смещение | Код |
|---|---|---|---|---|---|
| `JMP [L1]` | 000000 | 000004 | 000058 | 58 − 4 = 54 | 06000054 |
| `LOADR1 [B1]` | 000058 | 00005C | 00004A | 4A − 5C = −18 | 0AFFFFEE |
| `LOADR2 [B4]` | 00005C | 000060 | 000057 | 57 − 60 = −9 | 0EFFFFF7 |
| `SAVER1 [L1]` | 000062 | 000066 | 000058 | 58 − 66 = −14 | 16FFFFF2 |

Таблица настройки пустая, записей `M` нет: программа работает по любому адресу без настройки.

## Пример «Смешанная адресация»

`JMP [L1]`, `LOADR1 B1`, `LOADR2 [B4]`, `SAVER1 [L1]`. В таблице настройки одна строка - `000058` (`LOADR1 B1`, код `0900004A`), остальные команды с меткой - со смещением, как в предыдущем примере.

## Пример «Все 4 формата команд»

ТКО та же, что в лабе 1 (в ней есть `CALL` - формат 3 и `NOP` - формат 1). `CALL [Show]` - формат 3 с относительной адресацией: МКОП `09 * 4 + 2 = 26`, смещение в 2 байта: `260001`. `CALL Exit` - формат 3 с прямой адресацией: `250025`, попадает в таблицу настройки.

## Проверяемые ошибки

Все ошибки лабы 1, кроме неверного адреса загрузки, и ещё:
- адрес в `START` не 0;
- `[метка]` в режиме «только прямая», метка без скобок в режиме «только относительная»;
- `[метка]` у команды без адреса (формат 1 или 2);
- не закрыта скобка: `[B4`;
- на втором проходе - смещение не помещается в поле команды (в формате 3 - больше 2 байт).

В списке «Пример» 5 программ без ошибок (в том числе «Точка входа - метка» с `END L1`, запись `E 000058`) и 17 программ с ошибками.

## Контрольные вопросы

**Чем перемещаемая программа отличается от абсолютной?** Она транслируется с нуля и может быть загружена по любому адресу. Адреса, которые зависят от места загрузки, перечислены в таблице настройки.

**Что такое таблица настройки?** Список адресов команд, в которых записан адрес метки (прямая адресация). При загрузке по адресу X к адресу внутри каждой такой команды прибавляется X.

**Зачем записи M в двоичном коде?** Это таблица настройки внутри объектного модуля: загрузчик читает её из модуля вместе с кодом.

**Почему относительная команда не попадает в таблицу настройки?** В ней записано расстояние до метки. Если сдвинуть всю программу, расстояние не изменится.

**Как считается смещение?** Адрес метки минус адрес следующей команды. Отрицательное смещение - в дополнительном коде.

**Почему смещение от следующей команды, а не от текущей?** Когда процессор выполняет команду, счётчик команд уже указывает на следующую.

**Что меняют режимы адресации?** Какие записи операнда ассемблер принимает. В режиме «только относительная» программа получается полностью перемещаемой без таблицы настройки.

**Чем отличается МКОП у `LOADR1 B1` и `LOADR1 [B1]`?** Младшими двумя битами: `01` - прямая (`09`), `10` - относительная (`0A`).

**Почему в START только 0?** Перемещаемая программа считается от нуля, настоящий адрес загрузки становится известен только загрузчику.
