# Лабораторная работа №4

Однопросмотровый ассемблер для программы в абсолютном формате.

## Задание

Сделать то же, что в лабе 1, но исходный текст читается один раз. Итоговый объектный модуль должен совпасть с лабой 1.

- Код строки формируется сразу, когда строка прочитана.
- Если адрес метки в операнде ещё неизвестен (метка ниже), в код ставится заглушка, а в ТСИ запоминается адрес команды, которая ждёт эту метку.
- Когда встречается строка с этой меткой, её адрес вписывается во все команды, которые её ждали.
- На `End` проверяется, что меток без адреса не осталось.
- Трассировка: ассемблирование можно выполнять по одной строке и смотреть, как меняются ТСИ и двоичный код.

Директивы, форматы команд и ТКО те же, что в [лабе 1](lab1.md).

## Окно

```
+----------------------+-------------------------+-----------------------+
| Исходный текст       | ТСИ                     | Заголовок             |
| ТКО                  |                         | Двоичный код (H T E)  |
| Адрес загрузки       | Ошибки                  |                       |
+----------------------+-------------------------+-----------------------+
 [Шаг] [Полный проход] [Сброс]                            Пример: [   v]
```

- «Шаг» (F10) - обработать одну следующую строку исходного текста.
- «Полный проход» (F5) - обработать все оставшиеся строки до конца.
- «Сброс» - начать ассемблирование сначала.
- Строка, которая будет обработана следующей, подсвечивается жёлтым. Только что обработанная строка выделяется, вместе с ней выделяются её запись в двоичном коде и метка в ТСИ.
- В строке состояния написано, что сделал последний шаг: какой код получился, какая метка определилась и в какие команды вписан её адрес.
- Вспомогательной таблицы нет: при одном проходе она не нужна, код получается сразу.
- Ошибки одной таблицей, т.к. проход один.
- Если поменять исходный текст, ТКО или адрес загрузки, ассемблирование повторяется до того же шага.

ТСИ из трёх столбцов:

| Столбец | Что там |
|---|---|
| Метка | имя |
| Адрес | адрес метки, пусто - метка ещё не встретилась |
| Команды, ждущие адрес | адреса команд, где метка использована раньше, чем определена |

Метка без адреса и команда с заглушкой показаны серым.

## Что такое шаг

Шаг - это обработка одной строки исходного текста ассемблером, а не выполнение команды программы. Поэтому в «тело» подпрограммы (`CALL`) заходить не нужно: ассемблер ничего не выполняет, он только переводит строки в код по порядку.

## Обработка строки

Метка в начале строки:
- метки нет в ТСИ - добавить с текущим адресом;
- метка есть, но без адреса (её уже ждут) - записать адрес и вписать его во все команды, которые её ждали, список ожидания очистить;
- метка есть с адресом - ошибка «метка уже определена».

Метка в операнде:
- адрес известен - сразу подставить его в код;
- адрес неизвестен - поставить заглушку `??????` (у формата 3 - `????`), а адрес команды записать в ТСИ к этой метке.

## Пример «Без ошибок»

Программа та же, что в [лабе 1](lab1.md#пример-без-ошибок). Метка `L1` используется во второй строке, а определяется в девятой.

| Шаг | Строка | Что происходит | Код |
|---|---|---|---|
| 1 | `PROG START 100` | счётчик адреса = 000100, запись H | |
| 2 | `JMP L1` | L1 ещё нет, в ТСИ: L1 ждёт команда 000100 | 05?????? |
| 3 | `A1 RESB 10` | A1 = 000104 | резерв 0A |
| 4 | `A2 RESW 20` | A2 = 00010E | резерв 3C |
| 5 | `B1 WORD 40` | B1 = 00014A | 000028 |
| 6 | `B2 BYTE X"2F4C008A"` | B2 = 00014D | 2F4C008A |
| 7 | `B3 BYTE C"Hello!"` | B3 = 000151 | 48656C6C6F21 |
| 8 | `B4 BYTE 12` | B4 = 000157 | 0C |

| 10 | `LOADR2 B4` | B4 известна | 0D000157 |
| 11 | `ADD R1 R2` | | 1012 |
| 12 | `SAVER1 B1` | | 1500014A |
| 13 | `INT 200` | | 18C8 |
| 14 | `END 100` | меток без адреса нет, длина 000068, точка входа 000100 | |

|---|---|---|

|---|---|---|
| L1 | 000158 | |

Метки в ТСИ стоят в том порядке, в каком впервые встретились: `L1` первая, т.к. её использовали раньше всех.

| H | PROG | 000100 | 000068 | |

## Пример «Одну метку ждут несколько команд»

```
PROG    START   2000
        LOADR1  X
        LOADR2  X
        ADD     R1  R2
        SAVER1  X
        JMP     Fin
X       WORD    5
Fin     NOP
        END
```

После шага 6 у `X` в ТСИ три ждущие команды: `002000, 002004, 00200A`. На шаге 7 `X = 002012`, адрес вписывается сразу в три команды: `09002012`, `0D002012`, `15002012`.

## Пример «Метки определены раньше, чем используются»

Все метки стоят выше команд, которые их используют. Заглушек нет ни на одном шаге: адрес каждой метки уже известен, когда она встречается в операнде.

## Ошибки

Все ошибки лабы 1 остаются. Ошибки собираются все, ассемблирование после ошибки не останавливается: строка с ошибкой просто не даёт кода.

Отличия от лабы 1:
- «метка не определена» видно только на `End`: до этого метка могла встретиться ниже. Ошибка указывает на каждую команду, которая так и не получила адрес, такие записи в двоичном коде подсвечиваются;
- если у команды формата 3 адрес метки не помещается в 2 байта, это выясняется в тот момент, когда метка определилась, и ошибка указывает на ту команду, которая её ждала (пример «адрес метки не влез в 2 байта»);
- если точка входа в `END` - метка, которую только использовали, но не определили, ошибка «метка не определена».

В списке «Пример» 5 программ без ошибок и 17 с ошибками, в том числе с несколькими ошибками сразу.

## Контрольные вопросы

**Чем отличается от лабы 1?** Текст читается один раз. Код строки получается сразу, а адреса меток, которые ниже, вписываются потом, когда метка встретится. Результат тот же.

**Что добавилось в ТСИ?** Столбец с адресами команд, которые ждут адрес этой метки. Когда метка определяется, по этим адресам вписывается её адрес, а список очищается.

**Когда становится понятно, что метка не определена?** Только на `End`: до этого она могла встретиться ниже.

**Зачем трассировка?** Чтобы по шагам видеть, как ставятся заглушки и как они потом заполняются.

**Что лучше, один проход или два?** Один проход быстрее, текст читается один раз. Но весь код нужно держать в памяти, чтобы потом вписывать адреса, и для каждой метки хранить список ждущих команд.
