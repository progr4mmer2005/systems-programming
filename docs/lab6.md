# Лабораторная работа №6

Однопросмотровый ассемблер для программы в полном перемещаемом формате (раздельное ассемблирование).

## Задание

Объединить лабу 5 и лабу 3: исходный текст читается один раз, как в лабах 4–5, а программа в полном перемещаемом формате, как в лабе 3. Итоговый объектный модуль должен совпасть с лабой 3 по содержанию.

- `EXTDEF` (внешние имена) и `EXTREF` (внешние ссылки) сразу после `START`.
- В ТСИ признак внешнего имени.
- Таблица настройки из двух столбцов: адрес команды и имя внешней ссылки.
- Таблица внешних имён и список внешних ссылок.
- Сохранение объектного модуля в текстовый файл в порядке: заголовок, внешние имена, внешние ссылки, код, таблица настройки, конец (`H D R T M E`).
- Трассировка: кнопки «Шаг», «Полный проход», «Сброс».

Директивы `EXTDEF` / `EXTREF`, записи `D`, `R`, `M` и файл - как в [лабе 3](lab3.md). Один проход, заглушки, относительная адресация и режимы - как в [лабе 5](lab5.md).

### Управляющие секции

После `START` можно начинать дополнительные секции строкой `Имя CSECT`. Каждая секция получает собственный счётчик адреса от `000000`, ТСИ, `EXTDEF` и `EXTREF`. Одинаковые локальные метки в разных секциях не конфликтуют и разрешаются в пределах своей секции. Директивы `EXTDEF` и `EXTREF` задаются после `START` или `CSECT` соответствующей секции.

`CSECT` закрывает предыдущую секцию и начинает новую. Необязательный операнд `CSECT` задаёт точку входа закрываемой секции; у `END` он задаёт точку входа последней секции. Объектный модуль формируется отдельно для каждой секции с записями `H`, `D`, `R`, `T`, `M`, `E`.

## Окно

```
+----------------------+-------------------------+-------------------------------------+
| Исходный текст       | ТСИ                     | Заголовок              [Сохранить...] |
|                      |                         | Таблица настройки | Внешние имена   |
| ТКО                  |                         |                   | Внешние ссылки  |
| Адресация: [      v] | Ошибки                  | Двоичный код (H D R T M E)           |
+----------------------+-------------------------+-------------------------------------+
 [Шаг] [Полный проход] [Сброс]                                         Пример: [   v]
```

- «Шаг» (F10) - обработать одну строку, «Полный проход» (F5) - до конца, «Сброс» - сначала.
- Строка, которая будет обработана следующей, подсвечивается жёлтым.
- ТСИ из четырёх столбцов: метка, адрес, внешнее (1 - имя объявлено в `EXTDEF`), команды, ждущие адрес.
- Внешнее имя, у которого ещё нет адреса, показано серым и в таблице внешних имён, и в записи `D`.
- «Сохранить...» доступна, когда ассемблирование закончено без ошибок.

## Особенности одного прохода

**`EXTDEF`** стоит в начале, а сами метки - ниже. На строке `EXTDEF` имена запоминаются как внешние, адреса у них пока нет. Адрес появляется, когда встретится метка с этим именем. На `End` проверяется, что у всех имён из `EXTDEF` есть адрес.

**`EXTREF`** тоже стоит в начале, поэтому при использовании внешней ссылки уже известно, что это она:
- в код пишутся нули, в таблицу настройки - адрес команды и имя ссылки;
- запоминать команду в ТСИ не нужно: адрес ссылки в этом модуле не появится никогда, его подставит компоновщик;
- `[внешняя ссылка]` - ошибка сразу: расстояние до другого модуля неизвестно.

**Обычные метки** - как в лабе 5: прямая команда сразу в таблице настройки, неизвестный адрес или смещение - заглушка, вписывается, когда метка определится.

**Порядок записей `D`** - в порядке определения меток, как в лабе 3.

## Пример «Без ошибок»

Программа из [лабы 3](lab3.md):

```
first   START   0
        EXTDEF  buf     Str1
        EXTREF  Str2
Proc    LOADR1  Str3
        LOADR2  Str2
        ADD     R1      R2
        SAVER1  [Rez]
        JMP     Proc
Str1    WORD    3
Str3    WORD    1
Rez     WORD    ?
buf     BYTE    "Hello!"
        END
```

| Шаг | Строка | Что происходит | Код | Таблица настройки |
|---|---|---|---|---|
| 1 | `first START 0` | счётчик адреса = 000000 | | |
| 2 | `EXTDEF buf Str1` | buf и Str1 - внешние имена, адресов пока нет | | |
| 3 | `EXTREF Str2` | Str2 - внешняя ссылка | | |
| 4 | `Proc LOADR1 Str3` | Proc = 000000; Str3 ещё нет, ждёт команда 000000 | 09?????? | 000000 |
| 5 | `LOADR2 Str2` | внешняя ссылка: нули, в настройку адрес и имя | 0D000000 | + 000004 Str2 |
| 6 | `ADD R1 R2` | | 1012 | |
| 7 | `SAVER1 [Rez]` | относительная, Rez ещё нет | 16?????? | |
| 8 | `JMP Proc` | Proc известна | 05000000 | + 00000E |
| 9 | `Str1 WORD 3` | Str1 = 000012, внешнее имя получило адрес | 000003 | |
| 10 | `Str3 WORD 1` | Str3 = 000015, адрес вписан в 000000: `09000015` | 000001 | |
| 11 | `Rez WORD ?` | Rez = 000018, смещение 000018 − 00000E = 00000A вписано в 00000A: `1600000A` | резерв | |
| 12 | `buf BYTE "Hello!"` | buf = 00001B, внешнее имя получило адрес | 48656C6C6F21 | |
| 13 | `END` | меток без адреса нет, у buf и Str1 есть адреса, длина 000021 | | |

Итоговый объектный модуль. Записи те же, что в лабе 3, но записи настройки `M` стоят после кода `T`, перед концом `E`:

```
H first 000000 000021
D Str1 000012
D buf 00001B
R Str2
T 000000 04 09000015
T 000004 04 0D000000
T 000008 02 1012
T 00000A 04 1600000A
T 00000E 04 05000000
T 000012 03 000003
T 000015 03 000001
T 000018 03
T 00001B 06 48656C6C6F21
M 000000
M 000004 Str2
M 00000E
E 000000
```

## Ошибки

Все ошибки лабы 3 остаются. Ошибки собираются все, ассемблирование после ошибки не останавливается.

Отличия от лабы 3:
- «метка не определена» и «имя из `EXTDEF` не определено» видно только на `End`;
- `[внешняя ссылка]` - ошибка сразу на этой строке, а не на втором проходе.

В списке «Пример» 2 программы без ошибок и 15 с ошибками.

## Контрольные вопросы

**Чем отличается от лабы 3?** Результат тот же, но текст читается один раз, нет вспомогательной таблицы, адреса и смещения меток, которые ниже, вписываются потом.

**Чем отличается от лабы 5?** Добавились внешние имена и ссылки, таблица настройки с именем ссылки, записи `D` и `R`, сохранение в файл.

**Почему у имён из `EXTDEF` сначала нет адреса?** Они объявляются в начале программы, а метки с этими именами стоят ниже.

**Почему внешнюю ссылку не нужно запоминать в ТСИ, как метку ниже?** Её адрес в этом модуле не появится никогда: она определена в другом модуле, адрес подставит компоновщик. Достаточно записи в таблице настройки.

**Почему `[внешняя ссылка]` - ошибка?** Относительная адресация - это расстояние от команды до метки, а где окажется другой модуль, решает компоновщик.

**Совпадёт ли результат с лабой 3?** Да, те же записи. Отличается только порядок: в лабе 6 записи `M` идут после кода `T`.
