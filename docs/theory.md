# Теория

## Что делает ассемблер

Ассемблер переводит программу, записанную мнемониками, в машинный код. Например:

```
LD   R1  One     ->  05 01 1015
ADD  R1  R2      ->  0C 12
```

Результат оформляется как объектный модуль, который потом загружается в память.

## Основные понятия

- **Команда** - действие процессора: `LD R1 One` (загрузить в R1), `ADD R1 R2` (сложить), `CALL Show` (вызвать подпрограмму), `HALT` (стоп).
- **Регистр** - ячейка внутри процессора: `R0`–`R15`. В коде записывается номером.
- **Адрес** - номер ячейки памяти, записывается 4 hex-цифрами: `1000`, `101B`.
- **Метка** - имя для адреса, пишется в начале строки. Её адрес ассемблер считает сам.
- **Директива** - указание ассемблеру, а не процессору: `Start`, `End`, `WORD`, `BYTE`, `EXTDEF`, `EXTREF`.
- **ТКО** (таблица кодов операций) - список команд: мнемоника, код, длина.
- **ТСИ** (таблица символических имён) - список меток и их адресов.
- **Счётчик адреса** - адрес текущей строки. Начинается с адреса из `Start` и увеличивается на длину каждой строки.
- **Вспомогательная таблица** - результат первого прохода: адрес и код каждой строки, где вместо адресов меток пока пусто.
- **Объектный модуль** - результат работы: заголовок (имя, длина, адрес загрузки), код и служебные таблицы.

## Проблема ссылок вперёд

```
      LD   R1  One     <- здесь нужен адрес One
      ...
One   WORD 1           <- а определена One только здесь
```

Когда ассемблер читает первую строку, адрес `One` ещё неизвестен. Есть два способа решить это.

## Двухпросмотровый ассемблер (лабы 1–3)

Текст читается два раза.

Первый проход:
1. Для каждой строки запомнить текущий адрес.
2. Если есть метка - проверить её и занести в ТСИ.
3. Команду найти в ТКО, собрать первый байт, перевести регистры и числа. На месте адреса метки оставить заглушку.
4. Константы `WORD` и `BYTE` перевести сразу.
5. Увеличить счётчик адреса на длину строки.

Второй проход: к этому моменту ТСИ заполнена, поэтому вместо заглушек подставляются адреса меток. Если метки нет в ТСИ - ошибка.

Длина программы = конечное значение счётчика − начальный адрес.

## Однопросмотровый ассемблер (лабы 4–6)

Текст читается один раз, код формируется сразу.

1. Если адрес метки в операнде уже известен - сразу подставить.
2. Если нет - записать метку в ТСИ без адреса и запомнить, в какой команде она нужна. В код поставить заглушку.
3. Когда встретилась строка с этой меткой - назначить адрес и вписать его во все запомненные команды.
4. На `End` проверить, что в ТСИ не осталось меток без адреса.

Такой ассемблер быстрее, но весь код приходится держать в памяти, чтобы потом исправлять его.

## Форматы программ

**Абсолютный** (лабы 1, 4). Программа считается от конкретного адреса, например `1000`. Загрузить её можно только туда.

**Перемещаемый** (лабы 2, 5). Программа считается от нуля и может быть загружена по любому адресу. При загрузке к адресам внутри команд прибавляется адрес загрузки. Список команд, в которых нужно это сделать, - таблица настройки.

**Полный перемещаемый** (лабы 3, 6). Программа состоит из модулей, которые транслируются отдельно. Модуль указывает, какие свои имена он даёт другим (`EXTDEF`) и какие имена берёт у других (`EXTREF`). Адрес внешней ссылки неизвестен, поэтому в код пишутся нули, а в таблицу настройки - адрес команды и имя ссылки.

## Виды адресации

| Адресация | Что в команде | Нужна настройка |
|---|---|---|
| Регистровая (`ADD R1 R2`) | номера регистров | нет |
| Непосредственная (`INT 5`) | само число | нет |
| Прямая (`LD R1 One`) | адрес метки | да |
| Относительная (`LD R1 [One]`) | смещение = адрес метки − адрес следующей команды | нет |

Относительной адресации не нужна настройка: если сдвинуть всю программу, расстояние между командой и меткой не изменится. Отрицательное смещение записывается в дополнительном коде: −6 = `FFFA`.

С внешней ссылкой относительную адресацию использовать нельзя: где находится другой модуль, неизвестно, и смещение посчитать не получится.
