# Теория

## Что делает ассемблер

Ассемблер переводит программу, записанную мнемониками, в машинный код. Например:

```
LOADR1  B1      ->  0900014A
ADD     R1  R2  ->  1012
```

Результат оформляется как объектный модуль, который потом загружается в память.

## Основные понятия

- **Команда** - действие процессора: `LOADR1 B1` (загрузить в R1), `ADD R1 R2` (сложить), `JMP L1` (переход), `INT 200` (прерывание).
- **Регистр** - ячейка внутри процессора: `R0`–`R15`. В коде записывается номером.
- **Адрес** - номер ячейки памяти, записывается 6 hex-цифрами: `000100`, `00014A`.
- **Метка** - имя для адреса, пишется в начале строки. Её адрес ассемблер считает сам.
- **Директива** - указание ассемблеру, а не процессору: `START`, `END`, `WORD`, `BYTE`, `RESB`, `RESW`, `EXTDEF`, `EXTREF`.
- **ТКО** (таблица кодов операций) - список команд: мнемоника, код, длина.
- **ТСИ** (таблица символических имён) - список меток и их адресов.
- **Счётчик адреса** - адрес текущей строки. Начинается с адреса из `START` и увеличивается на длину каждой строки.
- **Вспомогательная таблица** - результат первого прохода: адрес каждой строки, МКОП (первый байт команды) и операнды.
- **Объектный модуль** - результат работы: заголовок `H` (имя, адрес загрузки, длина), записи кода `T`, конец `E` (точка входа) и служебные таблицы.

## Проблема ссылок вперёд

```
      JMP     L1       <- здесь нужен адрес L1
      ...
L1    LOADR1  B1       <- а определена L1 только здесь
```

Когда ассемблер читает первую строку, адрес `L1` ещё неизвестен. Есть два способа решить это.

## Двухпросмотровый ассемблер (лабы 1–3)

Текст читается два раза.

Первый проход:
1. Для каждой строки запомнить текущий адрес.
2. Если есть метка - проверить её и занести в ТСИ.
3. Команду найти в ТКО, взять её длину и собрать первый байт (МКОП). У директив `WORD`, `BYTE`, `RESB`, `RESW` посчитать, сколько байт они занимают.
4. Записать строку во вспомогательную таблицу: адрес, МКОП, операнды.
5. Увеличить счётчик адреса на длину строки.

Второй проход: к этому моменту ТСИ заполнена, поэтому адрес любой метки известен. Операнды переводятся в код, вместо меток подставляются их адреса. Если метки нет в ТСИ - ошибка.

Длина программы = конечное значение счётчика − начальный адрес.

## Однопросмотровый ассемблер (лабы 4–6)

Текст читается один раз, код формируется сразу.

1. Если адрес метки в операнде уже известен - сразу подставить.
2. Если нет - записать метку в ТСИ без адреса, а к ней - адрес команды, которая её ждёт. В код поставить заглушку `????`.
3. Когда встретилась строка с этой меткой - назначить адрес и вписать его во все ждущие команды. Список ждущих команд очистить.
4. На `End` проверить, что в ТСИ не осталось меток без адреса. Раньше это проверить нельзя: метка могла встретиться ниже.

Адреса вписываются по списку из ТСИ прямо в готовый код, исходный текст второй раз не читается. Поэтому это не второй проход.

Вспомогательная таблица не нужна: она передаёт данные от первого прохода ко второму, а здесь проход один.

Такой ассемблер быстрее, но весь код приходится держать в памяти, чтобы потом вписывать адреса, и для каждой метки хранить список ждущих команд. Итоговый объектный модуль такой же, как у двухпросмотрового.

**Трассировка** - пошаговая работа ассемблера: один шаг - одна строка исходного текста, после шага видно, как изменились ТСИ и двоичный код. Это не выполнение программы: ассемблер ничего не выполняет, а только переводит строки в код по порядку. Поэтому в тело подпрограммы (`CALL`) заходить не нужно.

## Как правильно называть

Двухпросмотровый или однопросмотровый - это **ассемблер**. Абсолютный, перемещаемый или полный перемещаемый - это формат **программы** (её объектного модуля). Ассемблер не бывает «абсолютным», он бывает «для программы в абсолютном формате».

| Лаба | Название |
|---|---|
| 1 | двухпросмотровый ассемблер для программы в абсолютном формате |
| 2 | двухпросмотровый ассемблер для программы в перемещаемом формате |
| 3 | двухпросмотровый ассемблер для программы в полном перемещаемом формате (раздельное ассемблирование) |
| 4 | однопросмотровый ассемблер для программы в абсолютном формате |
| 5 | однопросмотровый ассемблер для программы в перемещаемом формате |
| 6 | однопросмотровый ассемблер для программы в полном перемещаемом формате (раздельное ассемблирование) |

Например: «Нужно было написать программу для демонстрации работы двухпросмотрового ассемблера для программы в полном перемещаемом формате».

## Форматы программ

| Формат | Лабы | Куда можно загрузить | Кто исправляет адреса | Связь с другими модулями | Записи модуля |
|---|---|---|---|---|---|
| Абсолютный | 1, 4 | только по своему адресу | никто | нет | H, T, E |
| Перемещаемый | 2, 5 | куда угодно | загрузчик по таблице настройки | нет | H, T, M, E |
| Полный перемещаемый | 3, 6 | куда угодно | загрузчик и компоновщик | есть (`EXTDEF` / `EXTREF`) | H, D, R, M, T, E |

### Абсолютный

Программа посчитана под конкретный адрес, например `START 100`. Адрес загрузки задаёт сам программист, он сразу записан в объектный модуль. Загрузчик кладёт программу ровно туда и ничего не исправляет. Если это место занято, загрузить программу нельзя.

#### Почему адрес загрузки не может быть 0

Нулевой адрес - это **признак формата**. По заголовку `H` загрузчик решает, что делать с программой:
- `H PROG 000000` - перемещаемая: положить куда угодно и настроить адреса по таблице настройки;
- `H PROG 000100` - абсолютная: положить ровно по этому адресу и ничего не исправлять.

Если бы абсолютная программа могла начинаться с 0, загрузчик не отличил бы её от перемещаемой. В перемещаемом формате 0 - не настоящий адрес, а начало программы, к которому загрузчик прибавит адрес загрузки. В абсолютном формате адрес настоящий, поэтому 0 там нельзя: он занят под признак перемещаемой программы.

Ответ:

> «Программа в абсолютном формате - значит, адрес загрузки задаём мы, он настоящий, и загрузчик кладёт программу ровно туда. Нулевой адрес в заголовке означает перемещаемую программу, поэтому абсолютной программе он запрещён: иначе загрузчик не отличит её от перемещаемой.»

### Перемещаемый

Программу можно загрузить **по любому адресу**. Адрес загрузки выбирает не программист, а загрузчик: он берёт свободное место в памяти, и заранее этот адрес неизвестен.

- Программа считается от нуля (`START 0`), адреса в командах - смещения от её начала: «метка L1 - на 58-м байте от начала».
- К программе прилагается **таблица настройки** - список команд, в которых стоят адреса.
- Загрузчик выбирает место, например `5000`, и прибавляет его к адресам из таблицы настройки: `000058` + `005000` = `005058`.

Почему начальный адрес только 0: тогда настройка - одно сложение. С другим начальным адресом загрузчику пришлось бы его сначала вычитать, а смысла в нём нет, настоящий адрес всё равно выберет загрузчик.

Команды с относительной адресацией настройки не требуют: расстояние до метки при сдвиге программы не меняется.

### Полный перемещаемый

Это перемещаемый формат **плюс связь с другими модулями**.

- Программа делится на несколько модулей, каждый транслируется отдельно. Это и есть **раздельное ассемблирование**.
- Модуль сообщает, какие свои метки отдаёт другим модулям (внешние имена, `EXTDEF`) и какие чужие метки использует сам (внешние ссылки, `EXTREF`).
- Адрес чужой метки при трансляции неизвестен. Ассемблер пишет вместо него нули, а в таблицу настройки - адрес команды и имя внешней ссылки.
- Потом **компоновщик** соединяет модули и подставляет эти адреса.

Зачем раздельное ассемблирование: если поменять один модуль, перетранслировать нужно только его; модули могут писать разные люди; готовые модули (библиотеки) можно использовать в разных программах.

### Одной фразой

> **Перемещаемый** - значит, программу можно загрузить по любому адресу, а загрузчик исправит адреса по таблице настройки. **Полный** - значит, вдобавок в модуле есть внешние имена и внешние ссылки, чтобы его можно было соединить с другими модулями, оттранслированными отдельно.

## Внешние имена и внешние ссылки

| | Внешнее имя (`EXTDEF`) | Внешняя ссылка (`EXTREF`) |
|---|---|---|
| Смысл | «даю свою метку другим модулям» | «беру чужую метку из другого модуля» |
| Где определена метка | в этом модуле | в другом модуле, здесь её нет |
| Адрес при трансляции | известен, это адрес метки в модуле | неизвестен |
| Что попадает в объектный модуль | запись `D`: имя и адрес | запись `R`: имя |
| Что в коде команды | обычный адрес метки | нули, а в таблице настройки - адрес команды и имя ссылки |
| Ошибка | имя объявлено, но метки в модуле нет | метка с таким именем определена в самом модуле |

Пример. Модуль A содержит подпрограмму `Show` и объявляет `EXTDEF Show`. Модуль B вызывает её и объявляет `EXTREF Show`. Для A `Show` - внешнее имя, для B - внешняя ссылка. Одна и та же метка - внешнее имя в своём модуле и внешняя ссылка во всех модулях, которые её используют.

Компоновщик берёт из модуля A адрес `Show` (запись `D`), а в модуле B по таблице настройки находит команды с нулями на месте `Show` и вписывает туда этот адрес.

## Виды адресации

| Адресация | Что в команде | Нужна настройка |
|---|---|---|
| Регистровая (`ADD R1 R2`) | номера регистров | нет |
| Непосредственная (`INT 200`) | само число | нет |
| Прямая (`LOADR1 B1`) | адрес метки | да |
| Относительная (`LOADR1 [B1]`) | смещение = адрес метки − адрес следующей команды | нет |

Относительной адресации не нужна настройка: если сдвинуть всю программу, расстояние между командой и меткой не изменится. Отрицательное смещение записывается в дополнительном коде: −6 = `FFFFFA`.

С внешней ссылкой относительную адресацию использовать нельзя: где находится другой модуль, неизвестно, и смещение посчитать не получится.
