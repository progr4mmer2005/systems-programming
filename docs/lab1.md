# Лабораторная работа №1

Двухпросмотровый ассемблер для программы в абсолютном формате.

## Задание

Написать программу с окном, которая по исходному тексту и ТКО выполняет два прохода ассемблера и показывает промежуточные и итоговые таблицы.

Требования:
- окно из трёх частей и кнопки «Первый проход» и «Второй проход»;
- исходный текст и ТКО редактируются, строки можно вставлять и удалять;
- адрес загрузки задаётся пользователем;
- все адреса в 16-ричном виде;
- 4 формата команд;
- на первом проходе мнемоника команды заменяется МКОП - первым байтом в битовом представлении;
- метки проверяются на зарезервированные слова;
- второй проход доступен только после успешного первого;
- есть примеры без ошибок и с ошибками.

Директивы и формат команд описаны в [assignment.md](assignment.md#директивы).

## Окно

```
+----------------------+-------------------------+-----------------------+
| Исходный текст       | Вспомогательная таблица | Заголовок             |
| ТКО                  | ТСИ                     | Двоичный код (H T E)  |
| Адрес загрузки       | Ошибки 1-го прохода     | Ошибки 2-го прохода   |
+----------------------+-------------------------+-----------------------+
 [Первый проход] [Второй проход]                          Пример: [   v]
```

Заголовок объектного модуля показан отдельной строкой, как в методичке и на скриншотах Zasm: имя программы, длина, адрес загрузки (`PROG 000068 000100`). Тот же заголовок записан в объектный модуль первой записью `H`.

## ТКО по умолчанию

| Команда | Код | Длина | Операнды |
|---|---|---|---|
| JMP | 01 | 4 | метка |
| LOADR1 | 02 | 4 | метка |
| LOADR2 | 03 | 4 | метка |
| ADD | 04 | 2 | регистр, регистр |
| SAVER1 | 05 | 4 | метка |
| INT | 06 | 2 | число |
| SUB | 07 | 2 | регистр, регистр |
| NOP | 08 | 1 | - |
| CALL | 09 | 3 | метка |

В ТКО есть все 4 формата команд (1 байт - `NOP`, 2 - `ADD`, `SUB`, `INT`, 3 - `CALL`, 4 - `JMP`, `LOADR1`, `LOADR2`, `SAVER1`).

Регистр, с которым работает команда, записан в её названии: `LOADR1 B1` - загрузить `B1` в `R1`.

## Пример «Без ошибок»

```
PROG    START   100
        JMP     L1
A1      RESB    10
A2      RESW    20
B1      WORD    40
B2      BYTE    X"2F4C008A"
B3      BYTE    C"Hello!"
B4      BYTE    12
L1      LOADR1  B1
        LOADR2  B4
        ADD     R1  R2
        SAVER1  B1
        INT     200
        END     100
```

### Первый проход

Счётчик адреса начинается с `000100` и после каждой строки увеличивается на её длину. Мнемоника команды заменяется МКОП - первым байтом, который собирается из битов: код операции из ТКО (6 бит) и тип адресации (2 бита). У директив в столбце МКОП остаётся их название. Операнды пока остаются как в исходном тексте, метки в них заменит адресами второй проход. Первая строка - `START`: имя программы и адрес загрузки.

| Адрес | МКОП | Операнд 1 | Операнд 2 |
|---|---|---|---|
| PROG | START | 000100 | |
| 000100 | 05 | L1 | |
| 000104 | RESB | 10 | |
| 00010E | RESW | 20 | |
| 00014A | WORD | 40 | |
| 00014D | BYTE | X"2F4C008A" | |
| 000151 | BYTE | C"Hello!" | |
| 000157 | BYTE | 12 | |
| 000158 | 09 | B1 | |
| 00015C | 0D | B4 | |
| 000160 | 10 | R1 | R2 |
| 000162 | 15 | B1 | |
| 000166 | 18 | 200 | |

Сколько байт занимает строка:

| Строка | Байт | Почему |
|---|---|---|
| `JMP L1` | 4 | длина из ТКО |
| `RESB 10` | 10 = `0A` | 10 байт |
| `RESW 20` | 60 = `3C` | 20 слов по 3 байта |
| `WORD 40` | 3 | слово - 3 байта |
| `BYTE X"2F4C008A"` | 4 | 8 цифр, по 2 на байт |
| `BYTE C"Hello!"` | 6 | 6 символов |
| `BYTE 12` | 1 | число 0..255 - один байт |

Как получается МКОП:

| Команда | Код в ТКО | Биты | Адресация | МКОП |
|---|---|---|---|---|
| JMP | 01 | 000001 | 01 - прямая | 000001 01 = 05 |
| LOADR1 | 02 | 000010 | 01 - прямая | 000010 01 = 09 |
| LOADR2 | 03 | 000011 | 01 - прямая | 000011 01 = 0D |
| ADD | 04 | 000100 | 00 - без адреса | 000100 00 = 10 |
| SAVER1 | 05 | 000101 | 01 - прямая | 000101 01 = 15 |
| INT | 06 | 000110 | 00 - без адреса | 000110 00 = 18 |

ТСИ:

| Метка | Адрес |
|---|---|
| A1 | 000104 |
| A2 | 00010E |
| B1 | 00014A |
| B2 | 00014D |
| B3 | 000151 |
| B4 | 000157 |
| L1 | 000158 |

Конец программы - `000168`, длина `000068`.

### Второй проход

Операнды переводятся в код: метка - в адрес из ТСИ, регистры - в номера, числа и строки - в hex. Каждая строка вспомогательной таблицы становится записью объектного модуля.

Тип записи: `H` - заголовок (имя программы, адрес загрузки, длина), `T` - строка кода (адрес, длина в байтах, код), `E` - конец модуля и точка входа (операнд `END`, а если его нет - адрес загрузки). У каждого поля свой столбец, поля, которых у записи нет, остаются пустыми. У `RESB`, `RESW` и `WORD ?` / `BYTE ?` кода нет - только место.

| Тип | Имя | Адрес | Длина | Машинный код |
|---|---|---|---|---|
| H | PROG | 000100 | 000068 | |
| T | | 000100 | 04 | 05000158 |
| T | | 000104 | 0A |  |
| T | | 00010E | 3C |  |
| T | | 00014A | 03 | 000028 |
| T | | 00014D | 04 | 2F4C008A |
| T | | 000151 | 06 | 48656C6C6F21 |
| T | | 000157 | 01 | 0C |
| T | | 000158 | 04 | 0900014A |
| T | | 00015C | 04 | 0D000157 |
| T | | 000160 | 02 | 1012 |
| T | | 000162 | 04 | 1500014A |
| T | | 000166 | 02 | 18C8 |
| E | | 000100 | | |

Разбор нескольких строк:
- `JMP L1` = `05` + адрес L1 `000158`;
- `ADD R1 R2` = `10` + номера регистров `1` и `2`;
- `INT 200` = `18` + 200 = `C8`;
- `WORD 40` = 40 = `000028` (3 байта);
- `C"Hello!"` - коды символов: `H` = `48`, `e` = `65`, ...

Если поменять адрес загрузки на `200`, все адреса сдвинутся на `100`: `05000258` и т.д.

## Пример «Точка входа - метка»

Та же программа, но в конце `END L1` вместо `END 100`. Программа начинается с данных (`RESB`, `RESW`, `WORD`, `BYTE`), а первая команда, с которой надо начинать, - `L1 LOADR1 B1`. Ассемблер берёт адрес `L1` из ТСИ, запись конца - `E 000158`. Код и остальные записи те же.

## Пример «Все 4 формата команд»

Программа, в которой есть все 4 формата команд из ТКО по умолчанию: `CALL Show` (формат 3, адрес 2 байта) = `25` + `1012`, `NOP` (формат 1) = `20`. Текст записан просто в кавычках, как в методичке: `Text BYTE "Hello"` = `48656C6C6F`.

## Проверяемые ошибки

ТКО:
- пустая ячейка;
- повтор мнемоники или кода;
- мнемоника длиннее 6 символов;
- код не hex или больше `3F`;
- длина не от 1 до 4;
- мнемоника совпадает с директивой или регистром.

Первый проход:
- нет `START` в начале или нет `END`;
- неверный адрес загрузки (не hex, больше FFFFFF или равен 0);
- нет имени программы у `START`;
- повтор метки, метка совпадает с зарезервированным словом;
- команды нет в ТКО;
- операнды не подходят к формату команды;
- неверное значение в `WORD` (не 0..16777215), `BYTE` (не 0..255, нечётное число цифр в `X"..."`, не закрыта кавычка, строка длиннее 30 байт), `RESB` / `RESW` (не больше 0);
- точка входа в `END` вне программы или метки точки входа нет в ТСИ;
- метка на строке `END` (она указывала бы за конец программы);
- операнд в скобках `[метка]` - относительная адресация в абсолютном формате не поддерживается (она появится в лабе 2);
- выход за пределы памяти `FFFFFF`;
- строки после `END`.

Второй проход:
- метка не определена;
- у команды формата 3 адрес метки не помещается в 2 байта.

Строки с ошибками подсвечиваются, в сообщении указан номер строки.

В списке «Пример» есть 3 программы без ошибок и 16 программ с ошибками, в том числе с несколькими ошибками сразу.

## Контрольные вопросы

**Зачем два прохода?** Метки могут использоваться раньше, чем определены (`JMP L1` в начале, `L1` ниже). Первый проход находит адреса всех меток, второй подставляет их.

**Что делает первый проход?** Считает адреса строк, заполняет ТСИ и заменяет мнемоники на МКОП. Результат - вспомогательная таблица: адрес, МКОП, операнды.

**Что в столбце МКОП?** Первый байт команды: код из ТКО, сдвинутый на 2 бита (умножить на 4), плюс тип адресации. У директив там их название.

**Что делает второй проход?** Переводит операнды в код, подставляет адреса меток из ТСИ и формирует объектный модуль.

**Какие форматы команд?** Четыре, формат равен длине: 1 байт - без операндов, 2 - два регистра или число, 3 - адрес из 2 байт, 4 - адрес из 3 байт.

**Как собирается первый байт?** Старшие 6 бит - код операции, младшие 2 - тип адресации. `LOADR1` = `000010`, прямая = `01`, получается `00001001` = `09`.

**Почему код операции не больше 3F?** На него отведено 6 бит, `3F` = `111111`.

**Чем отличаются RESB / RESW от BYTE / WORD?** `BYTE` и `WORD` задают значение, `RESB` и `RESW` только резервируют место: `RESB 10` - 10 байт, `RESW 20` - 20 слов по 3 байта.

**Чем "...", C"..." и X"..." отличаются?** В `"..."` и `C"..."` записан текст, каждый символ - байт (`"Hello"` и `C"Hello"` - одно и то же). В `X"..."` записаны сами байты в hex, по 2 цифры на байт.

**Почему адрес L1 равен 000158?** Перед ней строки длиной 4 + 10 + 60 + 3 + 4 + 6 + 1 = 88 = `58h` байт, начало программы `000100`.

**Что за буквы H, T, E в двоичном коде?** Это типы записей объектного модуля: H - заголовок, T - строка кода, E - конец модуля и точка входа.

**END - это конец программы?** Конец текста для ассемблера: дальше он не читает. В машинный код `END` не попадает. При работе программа останавливается на своей команде остановки или возврата, а не на `END`.

**Что такое точка входа?** Адрес, с которого загрузчик начнёт выполнение программы. Задаётся операндом `END`: меткой (`END L1`) или адресом (`END 158`). Без операнда - адрес загрузки.

**Зачем писать в END метку, а не адрес?** Адрес не нужно считать вручную, и он не съедет, если вставить строки выше.

**Почему программа абсолютная?** Все адреса посчитаны от `000100`, по другому адресу она работать не будет.

**Какие слова нельзя использовать как метки?** Регистры `R0`–`R15`, директивы `START`, `END`, `WORD`, `BYTE`, `RESB`, `RESW` и команды из ТКО.
