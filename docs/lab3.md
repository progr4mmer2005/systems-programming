# Лабораторная работа №3

Двухпросмотровый ассемблер, раздельное ассемблирование (полный перемещаемый формат).

## Задание

Доработать лабу 2: программа может состоять из нескольких модулей, которые транслируются отдельно. Ассемблер, ТКО, режимы адресации и таблицы те же, что в лабе 2, добавляется только следующее.

- Директива `EXTDEF` - внешние имена: метки этого модуля, которые могут использовать другие модули. В строке одно или два имени.
- Директива `EXTREF` - внешние ссылки: имена из других модулей, которые использует этот модуль. В строке одно или два имени.
- `EXTDEF` и `EXTREF` стоят в начале программы, сразу после `START`, у них нет метки. Вместо `EXTDEF` можно писать `EXTNAME`, как в Zasm.
- Первый проход: обработать `EXTDEF` и `EXTREF`, в ТСИ добавить столбец с признаком внешнего имени.
- Второй проход: проверять, не является ли операнд внешней ссылкой. Для внешней ссылки в код пишутся нули, а в таблицу настройки - адрес команды и имя ссылки. Составить таблицу внешних имён и список внешних ссылок.
- Таблица настройки из двух столбцов: адрес настраиваемой команды и имя внешней ссылки.
- Сохранение объектного модуля в текстовый файл в порядке: заголовок, внешние имена, внешние ссылки, таблица настройки, код.

## Окно

```
+----------------------+-------------------------+-------------------------------+
| Исходный текст       | Вспомогательная таблица | Заголовок        [Сохранить]  |
|                      |                         | Таблица     | Внешние имена   |
|                      |                         | настройки   | Внешние ссылки  |
| ТКО                  | ТСИ (метка, адрес,      | Двоичный код (H D R M T E)    |
| Адресация: [      v] |  внешнее)               | Ошибки 2-го прохода           |
|                      | Ошибки 1-го прохода     |                               |
+----------------------+-------------------------+-------------------------------+
 [Первый проход] [Второй проход]                          Пример: [   v]
```

Кнопка «Сохранить...» доступна после второго прохода без ошибок. Щелчок по строке любой таблицы выделяет связанные строки в остальных: внешнее имя - строку, где определена метка, внешнюю ссылку - строку `EXTREF`.

## Пример «Без ошибок»

Программа со скриншотов Zasm 3.0 из методички, записанная командами ТКО по умолчанию.

```
first   START   0
        EXTDEF  buf     Str1
        EXTREF  Str2
Proc    LOADR1  Str3
        LOADR2  Str2
        ADD     R1      R2
        SAVER1  [Rez]
        JMP     Proc
Str1    WORD    3
Str3    WORD    1
Rez     WORD    ?
buf     BYTE    "Hello!"
        END
```

Модуль отдаёт другим метки `buf` и `Str1`, а метку `Str2` берёт из другого модуля.

ТСИ:

| Метка | Адрес | Внешнее |
|---|---|---|
| Proc | 000000 | 0 |
| Str1 | 000012 | 1 |
| Str3 | 000015 | 0 |
| Rez | 000018 | 0 |
| buf | 00001B | 1 |

Второй проход:
- `LOADR1 Str3` - прямая адресация: `09000015`, в таблицу настройки `000000`;
- `LOADR2 Str2` - внешняя ссылка: адрес неизвестен, в код пишутся нули `0D000000`, в таблицу настройки `000004 Str2`;
- `SAVER1 [Rez]` - относительная адресация: смещение `18 - 0E = 0A`, код `1600000A`, в таблицу настройки не попадает;
- `JMP Proc` - прямая адресация: `05000000`, в таблицу настройки `00000E`.

Таблица настройки:

| Адрес команды | Внешняя ссылка |
|---|---|
| 000000 | |
| 000004 | Str2 |
| 00000E | |

Внешние имена: `000012 Str1`, `00001B buf`. Внешние ссылки: `Str2`.

Объектный модуль (так же он сохраняется в файл):

```
H first 000000 000021
D Str1 000012
D buf 00001B
R Str2
M 000000
M 000004 Str2
M 00000E
T 000000 04 09000015
T 000004 04 0D000000
T 000008 02 1012
T 00000A 04 1600000A
T 00000E 04 05000000
T 000012 03 000003
T 000015 03 000001
T 000018 03
T 00001B 06 48656C6C6F21
E 000000
```

Записи: `H` - заголовок (имя, начальный адрес, длина), `D` - внешнее имя и его адрес, `R` - внешняя ссылка, `M` - строка таблицы настройки (адрес команды и, для внешней ссылки, её имя), `T` - код, `E` - точка входа.

## Пример «Две внешние ссылки»

`EXTREF Str2 Print` и добавлена команда `CALL Print` (формат 3, адрес 00000E). Для неё в код пишется `250000`, в таблицу настройки - `00000E Print`. Остальные адреса после неё сдвигаются на 3.

## Что делает компоновщик

Модули транслируются отдельно, каждый с нуля. Компоновщик (связывающий загрузчик) ставит модули в память друг за другом и по строкам таблицы настройки:
- строка без имени - прибавляет к адресу в команде адрес начала своего модуля;
- строка с именем внешней ссылки - находит это имя среди внешних имён (`D`) других модулей и записывает его настоящий адрес.

## Проверяемые ошибки

Все ошибки лабы 2 и ещё:
- у `EXTDEF` / `EXTREF` есть метка или нет ни одного имени;
- `EXTDEF` / `EXTREF` не в начале программы;
- имя в `EXTDEF` / `EXTREF` неправильное, совпадает с регистром, директивой, командой или именем программы, повторяется;
- одно имя и в `EXTDEF`, и в `EXTREF`;
- метка совпадает с внешней ссылкой;
- точка входа в `END` - внешняя ссылка (`END Str2`): начать выполнение с метки другого модуля нельзя;
- на втором проходе - имя из `EXTDEF` не определено в программе;
- на втором проходе - внешняя ссылка с относительной адресацией (`[Str2]`).

В списке «Пример» 2 программы без ошибок и 15 программ с ошибками.

## Контрольные вопросы

**Что такое раздельное ассемблирование?** Программа состоит из модулей, каждый транслируется отдельно. Связывает их компоновщик.

**Чем внешнее имя отличается от внешней ссылки?** Внешнее имя (`EXTDEF`) - метка этого модуля, которую он отдаёт другим. Внешняя ссылка (`EXTREF`) - имя из другого модуля, которое этот модуль использует.

**Почему для внешней ссылки в коде нули?** Её адрес станет известен только при компоновке. В таблицу настройки записывается, куда и чей адрес подставить.

**Почему внешнюю ссылку нельзя записать с относительной адресацией?** Смещение - расстояние до метки в этом же модуле. Где окажется другой модуль, неизвестно, расстояние до него посчитать нельзя.

**Зачем в ТСИ столбец «Внешнее»?** По нему второй проход составляет таблицу внешних имён.

**Почему EXTDEF и EXTREF стоят в начале?** Чтобы ассемблер заранее знал, какие имена внешние: при чтении команды с внешней ссылкой уже понятно, что это она.

**В каком порядке записан объектный модуль?** Заголовок, внешние имена, внешние ссылки, таблица настройки, код, конец.
