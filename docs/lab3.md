# Лабораторная работа №3

Двухпросмотровый ассемблер, раздельное ассемблирование (полный перемещаемый формат).

## Задание

Доработать лабу 2, чтобы модуль мог давать свои имена другим модулям и использовать чужие.

- Директива `EXTDEF` - внешние имена: метки этого модуля, доступные другим (в примере два имени).
- Директива `EXTREF` - внешние ссылки: имена из других модулей (одна-две).
- Первый проход: обработать эти директивы, в ТСИ добавить столбец-признак внешнего имени.
- Второй проход: проверять, не является ли операнд внешней ссылкой. Для внешней ссылки в код пишутся нули, а в таблицу настройки - адрес команды и имя ссылки.
- Таблица настройки из двух столбцов: адрес и имя. Для обычной настройки имя пустое.
- В правую часть окна добавить таблицу внешних имён и список внешних ссылок.
- Кнопка «Сохранить...» - запись объектного модуля в текстовый файл.

Порядок разделов в файле: заголовок, внешние имена, внешние ссылки, таблица настройки, код.

`EXTDEF` и `EXTREF` стоят в начале программы, сразу после `Start`, в одной строке можно указать два имени (по одному в каждом операнде). Вместо `EXTDEF` можно писать `ExtName`, а `ExtRef` - так директивы называются в Zasm на скриншотах. Все эти слова добавляются к зарезервированным.

Программа остаётся перемещаемой, как в лабе 2: `Start 0`, относительная адресация `[метка]`.

## Окно

```
+----------------------+-------------------------+------------------------------+
| Исходный текст       | Вспомогательная таблица | Заголовок                    |
|                      |                         | Таблица      | Внешние имена |
|                      |                         | настройки    | Внешние ссылки|
| ТКО                  | ТСИ (имя, адрес,        | Двоичный код                 |
|                      |      внешнее 1/0)       | Ошибки 2-го прохода          |
| Адрес загрузки       | Ошибки 1-го прохода     |              [Сохранить...]  |
+----------------------+-------------------------+------------------------------+
 [Первый проход] [Второй проход]                                  Пример: [   v]
```

Кнопка «Сохранить...» становится доступной после успешного второго прохода.

## Пример

Пример «Без ошибок»:

```
first   Start   000000
        EXTDEF  buf  Str1
        EXTREF  Str2
Proc    LD      R1   str3
        LD      R2   str2
        ADD     R1   R2
        SAV     R1   [Rez]
        JUMP    Proc
Str1    WORD    3
Str3    WORD    1
Rez     WORD    ?
buf     BYTE    "Hello!"
        End
```

Регистр букв в именах не важен: `str3` и `Str3` - одно имя.

### Результат

| Адрес | Строка | Код | Настройка |
|---|---|---|---|
| 000000 | `Proc LD R1 str3` | 05 01 0013 | 000000 |
| 000004 | `LD R2 str2` | 05 02 0000 | 000004 Str2 |
| 000008 | `ADD R1 R2` | 0C 12 | |
| 00000A | `SAV R1 [Rez]` | 0A 01 0007 | |
| 00000E | `JUMP Proc` | 15 0000 | 00000E |
| 000011 | `Str1 WORD 3` | 0003 | |
| 000013 | `Str3 WORD 1` | 0001 | |
| 000015 | `Rez WORD ?` | резерв | |
| 000017 | `buf BYTE "Hello!"` | 48 65 6C 6C 6F 21 | |

`SAV R1 [Rez]`: смещение 000015 − 00000E = 0007, в таблицу настройки не попадает.

Заголовок: `first 00001D 000000`.

ТСИ:

| Имя | Адрес | Внешнее |
|---|---|---|
| Proc | 000000 | 0 |
| Str1 | 000011 | 1 |
| Str3 | 000013 | 0 |
| Rez | 000015 | 0 |
| buf | 000017 | 1 |

Таблица настройки: `000000`, `000004 Str2`, `00000E`.
Внешние имена (в порядке ТСИ): `000011 Str1`, `000017 buf`.
Внешние ссылки: `Str2`.

### Файл

Формат строк в методичке не задан. Программа пишет каждую строку с буквы раздела: `H` - заголовок (имя, адрес загрузки, длина), `D` - внешнее имя, `R` - внешняя ссылка, `M` - строка таблицы настройки, `T` - код (адрес, длина, байты), `E` - конец модуля и точка входа. Резерв памяти (`WORD ?`) в файл не пишется, его место учтено в длине программы.

```
H first 000000 00001D
D Str1 000011
D buf 000017
R Str2
M 000000
M 000004 Str2
M 00000E
T 000000 04 05 01 0013
T 000004 04 05 02 0000
T 000008 02 0C 12
T 00000A 04 0A 01 0007
T 00000E 03 15 0000
T 000011 02 0003
T 000013 02 0001
T 000017 06 48 65 6C 6C 6F 21
E 000000
```

## Пример «Две внешние ссылки»

`EXTREF Str2 Print` и добавлена команда `CALL Print` (адрес 00000E). Для неё в код пишется `19 0000`, в таблицу настройки - `00000E Print`. Остальные адреса после неё сдвигаются на 3.

Двоичный код в окне показан записями объектного модуля, как в лабе 1: `H` - заголовок, `T` - строки кода с адресом и длиной, `E` - конец модуля.

## Новые ошибки

Первый проход:
- `EXTDEF` / `EXTREF` не в начале программы;
- метка у `EXTDEF` / `EXTREF`;
- у `EXTDEF` / `EXTREF` нет имён или имя неверное (зарезервированное слово, имя программы);
- одно имя и в `EXTDEF`, и в `EXTREF`;
- повтор имени в `EXTDEF` или `EXTREF`;
- метка совпадает с внешней ссылкой.

Второй проход:
- имя из `EXTDEF` не определено в модуле;
- внешняя ссылка с относительной адресацией (`[str2]`).

Остальные ошибки - как в лабе 2. В списке «Пример» две правильные программы и 14 программ с ошибками.

## Контрольные вопросы

**Зачем раздельное ассемблирование?** Большую программу пишут несколькими модулями, каждый транслируют отдельно, потом объединяют.

**Чем EXTDEF отличается от EXTREF?** `EXTDEF` - имена, которые модуль даёт другим. `EXTREF` - имена, которые модуль берёт у других.

**Почему для внешней ссылки в коде нули?** Её адрес станет известен только при компоновке.

**Зачем имя в таблице настройки?** Чтобы знать, что прибавлять. Пустое имя - адрес загрузки модуля, имя ссылки - адрес этого имени.

**Почему внешнюю ссылку нельзя использовать с относительной адресацией?** Расстояние до другого модуля заранее неизвестно.
