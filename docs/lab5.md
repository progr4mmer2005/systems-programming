# Лабораторная работа №5

Однопросмотровый ассемблер для программы в перемещаемом формате.

## Задание

Объединить лабу 4 и лабу 2: исходный текст читается один раз, как в лабе 4, а программа перемещаемая, как в лабе 2. Итоговый объектный модуль должен совпасть с лабой 2.

- Программа транслируется с нуля: `START 0` или `START` без адреса.
- Относительная адресация: операнд в квадратных скобках, `LOADR1 [B1]`.
- Режим адресации выбирается в окне: прямая и относительная, только прямая, только относительная.
- Таблица настройки и записи `M` в объектном модуле.
- Трассировка: кнопки «Шаг», «Полный проход», «Сброс».
- Примеры: только прямая адресация, только относительная, смешанная.

Директивы, форматы команд, ТКО, режимы и относительная адресация - как в [лабе 2](lab2.md). Один проход, заглушки и трассировка - как в [лабе 4](lab4.md).

## Окно

```
+----------------------+-------------------------+-----------------------+
| Исходный текст       | ТСИ                     | Заголовок             |
|                      |                         | Таблица настройки     |
| ТКО                  |                         | Двоичный код (H T M E)|
| Адресация: [      v] | Ошибки                  |                       |
+----------------------+-------------------------+-----------------------+
 [Шаг] [Полный проход] [Сброс]                            Пример: [   v]
```

- «Шаг» (F10) - обработать одну строку, «Полный проход» (F5) - до конца, «Сброс» - сначала.
- Строка, которая будет обработана следующей, подсвечивается жёлтым.
- ТСИ из трёх столбцов: метка, адрес, команды, ждущие адрес.
- Поля «Адрес загрузки» нет: перемещаемая программа всегда считается с 0, настоящий адрес выбирает загрузчик.
- При выборе примера режим адресации выставляется сам.

## Обработка команды с меткой

**Прямая адресация** (`LOADR1 X`):
- адрес команды **сразу** заносится в таблицу настройки. Для этого адрес метки не нужен: таблице важно только, в какой команде стоит адрес, а он сам может быть пока неизвестен;
- метка известна - подставить её адрес;
- метка неизвестна - заглушка `??????` и запомнить команду в ТСИ.

**Относительная адресация** (`LOADR1 [X]`):
- в таблицу настройки не заносится: смещение при сдвиге программы не меняется;
- метка известна (она выше) - сразу посчитать смещение, оно отрицательное;
- метка неизвестна - заглушка и запомнить команду в ТСИ.

Когда метка определяется, для каждой ждущей команды:
- прямая - вписать адрес метки;
- относительная - вписать смещение = адрес метки − адрес следующей команды (адрес команды + её длина).

Какая команда прямая, а какая относительная, видно по самой команде (тип адресации в МКОП), поэтому в ТСИ достаточно хранить адрес команды.

## Пример «Одну метку ждут несколько команд»

```
PROG    START   0
        LOADR1  X
        LOADR2  [X]
        ADD     R1  R2
        SAVER1  X
        JMP     [Fin]
X       WORD    5
Fin     NOP
        END
```

| Шаг | Строка | Что происходит | Код | Таблица настройки |
|---|---|---|---|---|
| 1 | `PROG START 0` | счётчик адреса = 000000 | | |
| 2 | `LOADR1 X` | прямая, X ещё нет, ждёт команда 000000 | 09?????? | 000000 |
| 3 | `LOADR2 [X]` | относительная, X ещё нет, ждёт команда 000004 | 0E?????? | 000000 |
| 4 | `ADD R1 R2` | | 1012 | 000000 |
| 5 | `SAVER1 X` | прямая, ждёт команда 00000A | 15?????? | 000000, 00000A |
| 6 | `JMP [Fin]` | относительная, Fin ещё нет | 06?????? | 000000, 00000A |
| 7 | `X WORD 5` | X = 000012: адрес в 000000 и 00000A, смещение в 000004: 000012 − 000008 = 00000A | 000005 | 000000, 00000A |
| 8 | `Fin NOP` | Fin = 000015: смещение в 00000E: 000015 − 000012 = 000003 | 20 | 000000, 00000A |
| 9 | `END` | меток без адреса нет, длина 000016 | | 000000, 00000A |

ТСИ после шага 6:

| Метка | Адрес | Команды, ждущие адрес |
|---|---|---|
| X | | 000000, 000004, 00000A |
| Fin | | 00000E |

Итоговый объектный модуль:

| Тип | Имя | Адрес | Длина | Машинный код |
|---|---|---|---|---|
| H | PROG | 000000 | 000016 | |
| T | | 000000 | 04 | 09000012 |
| T | | 000004 | 04 | 0E00000A |
| T | | 000008 | 02 | 1012 |
| T | | 00000A | 04 | 15000012 |
| T | | 00000E | 04 | 06000003 |
| T | | 000012 | 03 | 000005 |
| T | | 000015 | 01 | 20 |
| M | | 000000 | | |
| M | | 00000A | | |
| E | | 000000 | | |

## Пример «Отрицательное смещение»

```
PROG    START   0
One     WORD    1
Loop    LOADR1  [One]
        LOADR2  One
        ADD     R1  R2
        SAVER1  [One]
        JMP     [Loop]
        END     Loop
```

Все метки стоят выше команд, поэтому заглушек нет ни на одном шаге: смещение считается сразу. `JMP [Loop]` по адресу `000011`: `000003 − 000015 = −18`, в дополнительном коде `FFFFEE`, код `06FFFFEE`.

## Ошибки

Все ошибки лабы 2 остаются. Ошибки собираются все, ассемблирование после ошибки не останавливается.

Отличия от лабы 2:
- «метка не определена» видно только на `End`, ошибка указывает на каждую команду, которая так и не получила адрес или смещение;
- если смещение или адрес не помещается в поле команды, это выясняется в тот момент, когда метка определилась, и ошибка указывает на ждущую команду;
- команда с ошибкой убирается из таблицы настройки.

В списке «Пример» 7 программ без ошибок и 17 с ошибками.

## Контрольные вопросы

**Чем отличается от лабы 4?** Программа с нуля, есть относительная адресация, режимы адресации и таблица настройки.

**Чем отличается от лабы 2?** Текст читается один раз, нет вспомогательной таблицы, адреса и смещения меток, которые ниже, вписываются потом. Результат тот же.

**Почему команду с прямой адресацией можно сразу занести в таблицу настройки?** Таблице настройки нужен адрес команды, а не адрес метки. Адрес команды известен сразу.

**Что вписывается в ждущую относительную команду?** Не адрес метки, а смещение: адрес метки минус адрес следующей команды.

**Почему смещение для метки выше отрицательное?** Метка стоит раньше следующей команды, значит её адрес меньше.

**Совпадёт ли результат с лабой 2?** Да.
